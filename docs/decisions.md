## 2026-10-31 — Phase 0 infra and build rulings
- Supabase project lives on a new, dedicated Supabase account, project in Paris (eu-west-3), not London: the account exists only for this app, CLI create was forbidden, and the latency difference is negligible. Migrate later if wanted; spike data is throwaway. [my call, user supplied the account]
- Not Seeds' Supabase project, and not the Vercel Marketplace integration: the existing org is at the free-project limit, so a new account avoids pausing anything and leaves Seeds untouched. [my call, user agreed]
- Storage bucket is `perfume-spike-captures` (private); deleted at spike end. [my call]
- `SUPABASE_ANON_KEY` is a 5th server-side env var, read in the capture page and passed as a prop; no `NEXT_PUBLIC_*` vars. The anon key is non-secret and supabase-js needs a key even for signed uploads. [my call]
- Spike access uses Seeds' cookie + unlock form (`/spike/unlock`), not `?key=`; the plan's `?key=` text is superseded. Cost: type the passcode once per device. [my call]
- Security review (automated) flagged unlock brute force and a non-expiring HMAC session token. Ruling: no change. The passcode is 96-bit random so brute force is infeasible; revoke by rotating `SPIKE_PASSCODE`; the spike is throwaway and the gated data is bottle photos, deleted before Phase 1. Phase 1 uses real Supabase Auth. [my call]
- Thumbnail object URLs are revoked/downscaled in fix round 1, since the long iPhone session with full-res samples risks Safari memory pressure. [my call]

## Phase 0 spike findings

- **Auto-capture:** Seeds' minSharpness 2500 never fired on bottles; real bottle captures measured 328–437. Default is now 200 and auto-capture fires. 2 false fires on a static floor scene, both discarded as not perfume. Glare measured 0 on every real capture, so no glare gating; maxGlare stays off. [my call]
- **Identification:** the spec allows branding and shape evidence, so the strict "as printed" prompt was replaced. Naxos identified as Xerjoff from its X plaque and 1861 crest. [my call, spec]
- **Identification, round 2:** 9 of 14 captures fully correct. Misses: 2 partial names (Sospiro "CON…O", Diptyque sample "de Peau Eb…") and 1 bottle with no text, correctly left blank. No confident wrong identifications. [my call]
- **Sets:** the Matière Première lid shows only the house. UI now shows partial results instead of "Nothing recognised". [my call]
- **Back photo** only when needed. Phase 1 review: a poorly identified bottle gets a retake / add-back prompt. [user; prompt my call]
- **Truncated names → Phase 1:** use the most likely name from the house's range, flagged unclear, plus up to 2 alternatives. [user]
- **Fixtures:** hand-correction of `expected.json` skipped; fixtures are unverified model output. [user]
- **Timing:** extraction took about 1.5–9 s per bottle. [my call]
- **Not measured:** seconds per bottle, samples-mode accuracy, set-insert reading. The user moved to the build. [user]

## 2026-11-02 — Phase 1c deployed
- Review queue, AI enrichment and the Collection (Owned · Sets · Wishlist, perfume and set pages) deployed from `a0621e8`. Smoke: signed-out `/review`, `/collection`, `/collection/{id}` 307 to login; approve route 401. [my call]
- Approval is one security-definer RPC (`approve_result`): it locks the scan, matches or creates the perfume, creates the set once per set scan, then the item and photos. Double approve and parallel set approvals create exactly one item / one set. [my call]
- A perfume enters the **shared** catalogue only when every identity field (house, name, concentration, flanker) came unedited from a label read (`identified_from` label/both); edits are derived on the server, never trusted from the client. Otherwise it is private to the collection. [security review]
- Matching: normalised house + name + flanker, accents folded (`unaccent`); concentration exact or missing on either side. [review fix]
- Flags: "Hard to read" (unclear/missing/alternatives), "Already on your shelf", "New to the catalogue" (no match and not read from a label). A clear label creating a new perfume is not flagged, so bulk approve stays useful. [my call, as Seeds]
- Thumbnails: 240 px **JPEG** uploaded at capture as `thumb-{n}.jpg` (iOS Safari can't encode WebP). [my call]
- Fact edits are stored as overrides on every item of the perfume; the page shows the latest non-empty overrides. Setting a value back to the source removes the override. [my call]
- Enrichment fills only empty fields, labelled AI-suggested; unknown perfumes get no notes rather than invented ones. Real call (Xerjoff Naxos): 5.5 s, sensible. [my call]
- Deferred to later phases: wears, "Wear today", your stats and notes (Phase 2); smells like, layering, wishlist adding, add-from-text (Phase 3). [plan]

## 2026-11-02 — Phase 2 deployed
- Today (three picks with reasons, nudges, Wear), the Diary month view (log, edit, delete), perfume-page stats and notes, set tried marks, rating and worn filters, Stats, and a location setting. [plan]
- Wears are client-written under member RLS; a trigger copies `perfume_id` from the item and refuses items from another collection; `created_by` is always the signed-in member and can't be changed or cleared by members (00013–00016). Deleting an item keeps its wears. [security review]
- Location is per collection: UK postcode (postcodes.io, outward code stored) or browser location, both rounded to 2 dp. Weather from Open-Meteo, cached 15 min, attributed on Today and Settings. [my call]
- Today scoring: season, time of day, occasion, a weight fit against temperature (or season) with the lighter/bolder nudge, and rotation (worn recently down, untried samples and >6-week neglect up). Picks aren't stored: the last six days are replayed and anything shown yesterday or the day before is pushed down, so an unworn favourite rotates instead of topping the list all week. [review fix]
- Model reasons: `claude-haiku-5-5`, thinking disabled (adaptive thinking cost ~900 tokens and ~3 s), 8 s cap, cached per day and context; any failure keeps the rule reasons. Real calls: ~2.0 s. [my call]
- Logging a wear from Today doesn't re-rank the page (the card would vanish under its rating form); picks refresh on the next visit. [my call]
- Stats value: purchase price, else typical £/ml × size; unpriced items counted. Neglected = not worn in 90 days, linking to `/collection?worn=neglected`. Gaps are Phase 3. [plan]
- Not done: gaps, wishlist, smells like, layering, diary year view (Phase 3); delete account (two manual launch users). [plan]

## 2026-11-03 — Phase 3 deployed
- Wishlist: add by name ("Add without a photo"), by ticking "A tester" on a bottle in Review, or "Want this" on a gap suggestion. Rows show the stored reason ("Fills your hot-days gap"), else "Loved the sample · ★4.5", else "Added by you". "Move to owned" flips the status. [plan]
- Add by name: Claude (Sonnet, memory, no search) says which perfume the text means; the sheet shows it as "From text, not label" to check and edit. An existing match (collection or shared) is reused; otherwise the perfume is private to the collection with `sources` "text". Enrichment runs afterwards under the lookup quota. Real call: "diptique philosikos" → Diptyque Philosykos in 5.8 s. [plan]
- AI quota: `claim_ai` over `private.ai_calls`, service role only, rolling 24 h per collection: identify 30, gap suggestions 10, pair reasons 60. Cached results don't claim; a refused claim throws so nothing is cached. [plan]
- Smells like: 3·J(notes) + 2·J(accords) + 1 same family, ≥ 1.2, "very close" from 2.5. Layer with: needs a shared note or accord, scored by bridges + weight contrast + different family, ≥ 2; never a near-twin or something already in Smells like. Candidates: perfumes with an owned item (samples included). Haiku rewrites the lines; rule lines stay on any failure. [plan]
- Gaps (≥ 5 owned; a rule met by fewer than 2): hot days, cold days, date night, office, spring; at most 3. Suggestions exclude everything the collection has, wishlist and gone included. [plan, ruling]
- Diary year view: `/diary?y=YYYY`, wears per day in one oxblood ramp (#D9A397, #A44E47, #5A1F1F; validated against the card surface). [plan]
- Phase 2 minors fixed: wears can't be dated in the future (form); averages are exact and shown rounded down (3.95 → ★3.9, not a 4★ match); "£1k" not "£1.0k"; Stats shows zero tiles when empty; diary entries for perfumes no longer on the shelf aren't links; URL-seeded filters stop being sticky; "your location" casing; Today reasons cache key narrowed to what the prompt reads. [review]
